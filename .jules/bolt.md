## 2024-05-28 - ⚡ Bolt: [performance improvement] Optimizing Global Leaderboard Ranking Array Allocation
**Learning:** In `src/routes/leaderboard.js`, the `/api/leaderboard` route iterates over all users in the system to calculate rankings. The original code used `.map()` first to format objects, which created short-lived objects for every single user in the database (O(N) allocations), before running `.sort()` and slicing the top 25. This caused unnecessary memory allocations and garbage collection pressure on large datasets.
**Action:** When transforming large dataset arrays, defer `.map()` operations until after `.filter()`, `.sort()`, and `.slice()` have been applied to reduce memory overhead and avoid O(N) short-lived garbage object allocations. Ensure you create a shallow copy of the array (e.g., `[...arr]`) before sorting to avoid mutating cached data.
