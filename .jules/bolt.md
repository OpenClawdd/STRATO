## 2024-05-29 - [Optimization of Array Transformations before Mapping]
**Learning:** In scenarios where large cached dataset arrays (e.g. from the custom `store.getAll()` data store which returns a direct reference) are being processed (filtered, sorted, and sliced), calling `.map()` *before* `.sort()` and `.slice()` causes a large memory overhead because it instantiates object copies for the entire collection when only a fraction is needed. Additionally, `.sort()` mutates the source array, which can inadvertently mutate the in-memory cache if a shallow copy is not made beforehand.
**Action:** Always create a shallow copy of cached array references (e.g., `[...arr]`) before mutating methods like `.sort()`. Defer mapping operations (`.map()`) until after the dataset has been reduced via `.filter()`, `.sort()`, and `.slice()` to avoid O(N) garbage allocation overhead.
