## 2025-02-23 - [O(N) Bounded Selection for Top-N Queries]
**Learning:** Extracting the top 10/25 elements from a large data array by calling `.sort().slice()` scales poorly (O(N log N)). When combined with `.map()` before the sort, it forces V8 to allocate thousands of temporary objects just to immediately discard 99% of them. This is especially taxing on memory in a high-traffic Node environment where routes like `/api/leaderboard` or `/api/admin/analytics` retrieve the entire `store.getAll("users")` directly into memory.
**Action:** When a route requests only the "top N" items from an array, use a bounded insertion selection algorithm (O(N * N_top)) via a shared utility function, avoiding full-array sorting. Crucially, run heavy object transformations (like `.map`) *after* extracting the bounded subset to minimize garbage collection pressure.
