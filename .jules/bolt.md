## 2024-06-22 - Bounded Insertion Sort to extract top N items
**Learning:** For global leaderboards or analytics where we need to find the "top N" elements out of potentially hundreds or thousands of users/scores, using `Array.prototype.sort()` creates a massive CPU spike (O(N log N)) along with short-lived memory object allocations especially when chaining `.map()` on the entire dataset before sorting it. This pattern appears in multiple files (`leaderboard.js`, `admin.js`, `notifications.js`).
**Action:** Implemented an O(N) bounded insertion sort in `src/utils/sort.js` (`getTopK`) to compute the top elements incrementally. Applied this utility consistently across the analytics and leaderboard routes. Furthermore, filtering was moved into the same loop pass as the bound to prevent redundant array allocations, and the `.map()` transformation now properly occurs only on the finalized small output array, bypassing processing the full dataset.
